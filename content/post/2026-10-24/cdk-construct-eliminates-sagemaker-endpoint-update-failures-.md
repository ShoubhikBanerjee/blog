# CDK Construct Eliminates SageMaker Endpoint Update Failures with Auto Scaling

Updating an Amazon SageMaker AI real‑time endpoint configuration (changing instance type, count, or environment variables) through AWS CloudFormation or the AWS CDK can cause deployment failures.

## 🔍 Overview
- CloudFormation tries to update the endpoint while the scalable target is still registered.
- SageMaker blocks the endpoint update before CloudFormation reaches the auto‑scaling resources.
- If the scalable target is deregistered manually via the AWS CLI, the deployment succeeds, but CloudFormation does **not** re‑register the auto‑scaling resources. The endpoint runs without scaling and no error is reported.
- The stack’s rollback also fails (`UPDATE_ROLLBACK_FAILED`), leaving the stack in a broken state that requires manual console intervention.

## ⚙️ How It Works
A reusable CDK construct replaces the native `AWS::ApplicationAutoScaling::ScalableTarget` and `AWS::ApplicationAutoScaling::ScalingPolicy` resources with three custom resources that orchestrate the deregister‑register cycle around the endpoint update.

| Custom Resource | Purpose |
|-----------------|---------|
| **Deregister** | Removes the scalable target before the endpoint update begins. |
| **Register Scalable Target** | Waits for the endpoint to reach *InService* status, then registers the scalable target. |
| **Attach Scaling Policy** | Waits for the scalable target to be queryable, then applies the target‑tracking scaling policy. |

- The construct enforces explicit dependency ordering with `node.add_dependency` calls in CDK.
- Each custom resource is backed by a Step Functions state machine and Lambda functions.
- A `ConfigHash` property forces CloudFormation to re‑invoke the Lambda functions whenever a configuration value changes.

## 📦 Implementation Details
- The deployed stack contains:
  - 3 custom resources (Deregister, Register Scalable Target, Attach Scaling Policy)
  - 2 Step Functions state machines
  - 12 Lambda functions
    - 5 functions are the construct’s own handlers (one for Deregister and an `on_event`/`is_complete` pair for each asynchronous resource).
    - 7 functions are generated by the CDK provider framework.
- Provider `total_timeout` limits:
  - 1 hour for Register Scalable Target
  - 15 minutes for Attach Scaling Policy
- You do not need to write or maintain the framework‑generated functions; they are included automatically.

## ✅ Benefits
- Update endpoint configuration **and** auto‑scaling parameters in a single deployment without manual steps.
- Eliminates the hidden failure where the endpoint runs without auto scaling and no error is shown.
- Prevents `UPDATE_ROLLBACK_FAILED` scenarios, keeping the CloudFormation stack healthy.
- Provides deterministic ordering of deregister → endpoint update → register → attach policy.
