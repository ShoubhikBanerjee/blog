# TabPFN-TS Brings Zero-Shot Forecasting to Tabular Foundation Models

TabPFN-TS frames univariate time-series forecasting as tabular regression, using TabPFN and lightweight feature engineering to produce point and probabilistic forecasts. Its paper was accepted to the NeurIPS 2024 TRL and TSALM workshops, and the package’s v1.3.0 release uses TabPFN-3.5 by default.

## 🔍 Overview

The method transforms a time series into a table, adds engineered features, runs regression with TabPFN, and uses the regression results as forecasts. Multivariate targets are handled as N independent univariate forecasts.

The work reports performance on par with top-tier models across both GIFT-EVAL metrics, and TabPFN-TS is ranked first on the GIFT-EVAL benchmark. The paper is available in a newer version, and the project released v1.0.0 with AutoSeasonalFeatures and improved CalendarFeatures.

## 🧩 How it works

TabPFN-TS treats forecasting as univariate regression using target history and known-future covariates. It supports zero-shot forecasting without training, as well as point and probabilistic forecasts.

| Input or feature | How TabPFN-TS handles it |
|---|---|
| Known dynamic covariates, such as holidays | Supported when future values are supplied in `future_df`. Numeric and boolean covariates also receive lag and trailing-mean features. |
| Past dynamic covariates, such as weather observations | Dropped because future values are unavailable. |
| Static covariates, such as item ID or store size | Currently dropped. |
| Engineered temporal features, such as calendar and sin/cos features | Automatically generated by `TABPFN_TS_DEFAULT_FEATURES`. |

`KnownCovariateLagFeature`, the first feature in `TABPFN_TS_DEFAULT_FEATURES`, adds three columns for each numeric or boolean known covariate: lag 1, lag at the season length, and a trailing mean over one season. Season length comes from the timestamp frequency. Features are computed per series over the context and horizon, and horizon rows use covariate values rather than the target.

On 25 fev-bench tasks with numeric known covariates, this feature lowers SQL by 4.5% on the default v3.5 model: 21 of 25 tasks improved, while the worst task increased by 1.5%. The largest gains were on temperature-driven load forecasting.

## ⚙️ Models and availability

- As of v1.3.0, TabPFN-3.5 is the default in both `LOCAL` and `CLIENT` mode. This model is pretrained purely on synthetic data. The defaults require `tabpfn>=9.0.0` and `tabpfn-client>=0.5.3`.
- The finetuned TabPFN-TS-3 checkpoint from the TabPFN-3 report remains available. Earlier defaults shipped this checkpoint and required `tabpfn>=8.0.0`.
- `tabpfn-client` is included as the default engine, allowing fast inference without requiring a user’s own GPU.
- Install the package with `pip install tabpfn-time-series`.
