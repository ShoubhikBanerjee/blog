# AWS Quick powers an AI‑driven product development lifecycle with human approval

AI‑PDLC (AI‑Driven Product Development Lifecycle) shows how enterprises can accelerate product creation by stitching together fragmented knowledge sources with AWS Quick agents and keeping a human in the loop.

## 🔍 Overview
The AI‑PDLC framework strings together six specialist agents built on AWS Quick, an Orchestrator that guides a single conversation, and coding agents accessed via the open Agent Client Protocol (ACP).  At every stage a human approval gate must be satisfied, and all artifacts are stored in a shared space that ties decisions back to their source data.

## 🧩 How it works
- **Enterprise connectors** pull context from Slack, Outlook, Jira, Salesforce, SharePoint, ServiceNow, and many other sources.
- AWS Quick builds a **personal knowledge graph** that links people, projects, and decisions across those tools.
- The **Orchestrator** reads each specialist’s question framework at runtime, asks targeted questions, and dispatches artifact generation to the appropriate agent.
- A **single conversation** drives the entire journey; the pipeline advances only after human approval at each step.
- All generated artifacts land in a common markdown file (`prototype_spec.md`) that contains acceptance criteria, personas, screens, and data model, with every decision traceable to its source.

## ⚙️ Six specialist agents
| Agent | Responsibility |
|-------|-----------------|
| Discovery | Guides structured pain‑point analysis via Q&A, URL ingestion, and direct pulls from Slack, Jira, support tickets, Salesforce, and research repositories; scores pain points and produces a Pain Point Board. |
| Prioritize | Scores each use case on two transparent 0–10 frameworks (LLM capability match, tool availability, user acceptance **or** feasibility, business impact, effort); generates a Scoring Matrix that can be opened to trace why one use case outranks another. |
| Working Backwards | Generates a full PR/FAQ using the Amazon Working Backwards method, adding customer and internal FAQs covering unit economics, failure modes, regulatory risk, and competitive landscape. |
| Spec Generator | (Implicit in the workflow) consolidates output into `prototype_spec.md`. |
| Designer | (Implicit) creates design artifacts that flow into the specification. |
| Orchestrator | Leads the conversation, reads specialist frameworks, asks targeted questions, and routes artifact creation; presents human‑approval prompts before advancing. |

## 📈 End‑to‑End lifecycle
The AI‑PDLC spans eight phases, with the first four handled by the six AWS Quick agents and the last four by coding agents such as Kiro:
- **Discover** – Discovery agent collects and scores pain points.
- **Decide** – Prioritize agent ranks use cases.
- **Design** – Working Backwards and Designer agents produce PR/FAQ and design artifacts.
- **Prototype** – Spec Generator consolidates into a prototype specification.
- **Engineer** – Coding agents (e.g., Kiro, Claude Code) build from the specification via ACP.
- **Ship** – Coding agents deliver the product.
- **Operate** – Production data flows back into Discovery, closing the loop.
- **Learn** – Continuous improvement driven by new signals.

## 🛠️ Coding agents & ACP
- AWS Quick can delegate development tasks to AI coding agents using the **Agent Client Protocol (ACP)**, an open JSON‑RPC 2.0 standard with no vendor lock‑in.
- Customers may invoke their preferred coding agent—such as **Kiro** or **Claude Code**—to build against the specification generated by AI‑PDLC.

## ✅ Human approval & traceability
- A **human approval gate** exists at every stage; the pipeline proceeds only after the gate is cleared.
- Every decision is linked back to its source data, ensuring full traceability across Slack, Outlook, Jira, Salesforce, SharePoint, ServiceNow, and other enterprise systems.

## 📊 Consistent evaluation with UAEF
- The **Unified Agent Evaluation Framework (UAEF)** provides a framework‑agnostic way to score agents across different SDKs (LangGraph, LangChain, Strands Agents, Bedrock AgentCore).
- UAEF uses adapters to convert native traces into a canonical **AgentTrace**, then scores the trace with **36 built‑in metrics across 7 quality dimensions** (tool calling, response quality, responsible AI, performance, multi‑turn conversation, multi‑agent coordination, reasoning).
- Results are stored in **Amazon DynamoDB** (metadata) and **Amazon S3** (full results) and generate reports that help teams detect regressions, understand changes, and close the evaluation‑learn loop.
- UAEF can invoke an agent given an ARN or HTTP endpoint, collect responses, and adapt them in a single step.
